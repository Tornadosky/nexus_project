# LLM Skill Extension for NEXUS

## Overview
This extension adds LLM-generated skills for NEXUS. Instead of relying only on manually designed symbolic skills, a LLM proposes a structured skill hierarchy, which is validated, compiled into executable JAX reward functions and trained by the existing NEXUS pipeline. The resulting policies are at the end compared to the hand-designed baselines.

### schema.py
Defines the safe representation used by the LLM.
Contains:
- Reward Term
- SkillSpec
- NexusSkillSet
  
No executable code is generated by the LLM. Everything is represented as structured data.

### interpreter.py
Converts the validated skill specification into executable JAX components.

- Safely evaluates symbolic activation rules.
- Maps reward vocab into JAX reward functions.
- Builds skill masks.
- Creates the symbolic meta-policy.
- Produces a policy module compatible with the NEXUS training pipeline.

### client.py
Wrapper around the LLM.
- Supports OpenAI, HuggingFace or mock backends.
- Builds chat requests.
- Extracts and parses JSON responses.
- Provides a safe mock output for debugging without an API.

### pipeline.py
Coordinates the skill generation process.
- Builds prompts from environment information.
- Calls the LLM.
- Validates returned JSON.
- Converts the JSON into the NexusSkillSet schema.
- Saves generated skillsets.

### refinement_loop.py
Prototype for implementing iterative skill improvement:
1. Generate skill set
2. Train
3. Collect metrics by evaluation
4. Summarize metrics
5. Feed metrics back to LLM
6. Generate improved skill set
- Not yet integrated into the standard training workflow.

### env/env_registry.py
Environment metadata used during skill generation for constructing prompts:
- Semantic observation fields
- Task description

### scripts/run_llm_experiment.py
Runs a complete LLM experiment.
```Environment -> Generate skills -> Validate -> Comple -> Train -> Save metrics```

### scripts/run_llm_comparison.py
Runs both hand-designed NEXUS policy and LLM-generated policy and compares the resulting training performance for each.

## Workflow
```
Environment 
↓

↓

↓
LLM client
↓

↓
Interpreter

JAX policy module 
↓
Hierarchical AC-PQN Training
↓
Performance Comparison
```

### Experiments run 
Generate and train an LLM policy:
```bash
python scripts/run_llm_experiment.py \
    --env WalkerWalk \
    --config configs/walker.yaml
```
Compare against the hand-designed policy.
```bash
python scripts/run_llm_comparison.py \
    --env WalkerWalk \
    --config configs/walker.yaml \
    --seeds 3
```
Generate a single skillset.
```bash 
python test_llm.py 
```
