# Rollout videos: state-only vs state+RGB

Generated by `tools/make_state_plus_rgb_videos.py` from the saved policies in `~/runs_spr/` (no retraining). Every arm is a 250-step greedy rollout in a 1-env vision environment.

## What the frames show

The image is a 64x64 **GRAYSCALE** 3-frame stack from the MuJoCo-Warp camera render. It is not colour; "RGB" throughout this project is a misnomer inherited from the flag name.

* For **state+RGB** arms that image is the actor's input, and the caption says how strongly that seed's actor depended on it -- the LARGEST single pixel corruption, named. It does NOT quote the stored `actor_uses_pixels` boolean; see below.
* For **state-only** arms the actor has no camera pathway at all. The image is a scene view only, and every frame says so. Do not read it as something the policy is looking at.

## Corrected camera verdicts

The captions were rewritten in the correction pass. The stored `actor_uses_pixels` boolean thresholds the MEDIAN of {frozen_first, random_replay, zeros} at 30%, a bar calibrated on `RGB_PROPRIO: none` actors whose only input is the camera. An actor that also holds the privileged state can ride it through a corrupted frame, so the median under-reads, and it hides disagreement between the conditions.

**All three WalkerWalk seeds use their camera**: holding the image at the t=0 frame costs 94.9% / 74.2% / 80.2%, and the independent in-training probe reads 0.098 / 0.099 / 0.117 across the three. The earlier "seed 0 ignores its camera" reading was an artifact of the median rule. Cartpole and cheetah show no camera use on any seed. Full per-condition tables: `../figures/README.md`.

**If a video's baked-in caption still says a walker seed "IGNORED its camera", that file predates the correction and should be regenerated** -- delete it and re-run the driver.

## What these videos do NOT claim

* A single 250-step rollout is an illustration, not a measurement. The numbers to cite are in `../figures/README.md`, whose PRIMARY metric is the training return over 128 envs, not the 5-episode eval.
* Side-by-side files pair one seed of each arm; two walker pairings are provided. The walker state-only seed-0 video carries a note that its evaluation contains one collapsed episode. That episode is NOT excluded from any analysis: eval reset keys depend only on (episode, seed), so it started from the same state as the state+RGB arm's episode 4, which scored 0.652. It is a paired outcome, not contamination.
